# РЖАВЫЙ СИГНАЛ / RUST SIGNAL

Браузерная игра с шестью эпизодами, персонажами, боссами, руководством и энциклопедией. Стартовая страница — `index.html`, сама игра — `/play/`. Для игроков установка ПО не требуется.

Проект предназначен **только для публикации на веб-сервере**. Доступны статический сайт и серверный рейтинг на Node.js со встроенным SQLite. Код и документация не предполагают конкретных доменов, VPN-панелей, сертификатов или сетевой схемы.

## Варианты установки на VPS

Перед запуском скриптов проверьте действующие `nginx -t`, владельца HTTP/HTTPS-портов и наличие других сайтов/VPN-служб. **Не запускайте универсальный установщик на сервере с нестандартным Nginx или TLS-маршрутизацией без выбора подходящего режима.** Все домены ниже — вымышленные примеры из зарезервированных зон `example.com` и `example.net`.

### 1. Обычный VPS с системным Nginx (Ubuntu / Debian)

Установка и сборка из репозитория (при необходимости устанавливаются отсутствующие компоненты):

```sh
curl -fsSL https://raw.githubusercontent.com/serbo26-lab/RUST-SIGNAL/main/deploy/vps.sh | sudo sh -s -- install game.example.com
```

Для доступа только по HTTP и IP вместо домена можно использовать `install` без аргумента. Обновление уже установленной игры:

```sh
curl -fsSL https://raw.githubusercontent.com/serbo26-lab/RUST-SIGNAL/main/deploy/vps.sh | sudo sh -s -- update
```

Этот режим создаёт собственную конфигурацию сайта и API. Скрипт должен отказаться от установки при конфликте с уже управляемым приложением. Для существующего VPN-шлюза с отдельной схемой HTTPS выберите один из следующих режимов.

### 2. Замена отдельного сайта, который уже обслуживает выбранный домен

```sh
curl -fsSL https://raw.githubusercontent.com/serbo26-lab/RUST-SIGNAL/main/deploy/replace-domain.sh | sudo sh -s -- game.example.com
```

Подходит только для виртуального хоста, который можно безопасно отделить от остальных. Проверяются конфликты, делается резервная копия исходной конфигурации, а после ошибки выполняется откат. Если файл конфигурации разделяется с другим сайтом, содержит неоднозначные условия или обслуживает VPN-трафик, операция должна завершиться отказом. Не используйте для замены общего `default_server`.

### 3. Только статические файлы в отдельном веб-каталоге

Для VPS, где порт TLS принадлежит VPN/proxy-программе, используется собственная сборка Nginx либо маршрутизация уже настроена и **не должна меняться**:

```sh
curl -fsSL https://raw.githubusercontent.com/serbo26-lab/RUST-SIGNAL/main/deploy/selfmask-webroot.sh | sudo sh -s -- install game.example.com /var/www/example-game
```

Укажите **свой** веб-каталог, уже содержащий `index.html` и не содержащий чужих файлов, кроме допустимого `.well-known`. Скрипт не меняет конфигурации Nginx, TLS, VPN, прослушиваемые порты и файлы ACME. Страница и игра работают; **онлайн-рейтинг не будет доступен**, пока `/api/` не подключён к отдельному защищённому бэкенду.

Обновление статического сайта:

```sh
curl -fsSL https://raw.githubusercontent.com/serbo26-lab/RUST-SIGNAL/main/deploy/selfmask-webroot.sh | sudo sh -s -- update game.example.com /var/www/example-game
```

### 4. Nginx stream/SNI: отдельный HTTPS-сайт за существующим шлюзом

Для конфигурации, где **действующий** Nginx `stream` принимает TLS и его SNI-маршрут `default` уже ведёт к локальному HTTPS-серверу Nginx, можно создать *только новый именованный виртуальный хост* на имеющемся внутреннем TLS-порту. Сценарий **не переписывает** существующие `stream`-маршруты, параметры VPN, остальные сайты или сертификаты.

```sh
curl -fsSL https://raw.githubusercontent.com/serbo26-lab/RUST-SIGNAL/main/deploy/stream-default-site.sh -o /tmp/rust-signal-stream.sh
sh -n /tmp/rust-signal-stream.sh
sudo sh /tmp/rust-signal-stream.sh install game.example.com 8443 /etc/ssl/example-game/fullchain.pem /etc/ssl/example-game/privkey.pem tls_routes
```

Здесь `8443` — **пример** внутреннего HTTPS-порта; `tls_routes` — **пример** имени переменной из существующей директивы `map $ssl_preread_server_name $tls_routes`, передаваемый **без знака `$`**. Замените порт, переменную и пути сертификата своими значениями. Скрипт проверяет, что указанный map реально используется в `proxy_pass` и что его `default` ведёт на выбранный HTTPS-порт, а не в VPN/Reality. При другой схеме он должен отказаться от установки.

Установщик собирает игру, устанавливает изолированный loopback-only Node.js/SQLite API и добавляет один новый HTTPS-сайт. Выполняет `nginx -t`, плавное `reload` и проверки HTML, JS, CSS, графики и API через SNI. При сбое публикации удаляет только созданный им виртуальный хост. Если сборка и API уже подготовлены, но публикация не прошла, используйте `resume` с теми же пятью аргументами **после имени действия**; после успешной установки для обновлений — `update`.

Нельзя использовать этот режим, если `default`-маршрут SNI ведёт в VPN-службу вместо HTTPS-сервера или если домен уже обслуживается другим виртуальным хостом.

## Онлайн-рейтинг и безопасность

Серверный рейтинг работает через `/api/`, а процесс Node.js слушает только `127.0.0.1:32741`. SQLite хранится вне веб-каталога в `/var/lib/rust-signal/leaderboard/` с ограниченным доступом. На **каждом VPS собственная база**; при установке на несколько серверов рейтинги автоматически не объединяются. Браузерную игру нельзя сделать полностью защищённой от накрутки результатов без серверной проверки самого игрового процесса.

На серверах с VPN-сервисами не следует давать установщикам право переписывать общие конфигурации Nginx, переназначать `443`, читать ключи других приложений или очищать каталоги сертификатов. Перед любым изменением необходим независимый бэкап и проверка действующего маршрута.

## Разработка и проверки

Публичный исходный снимок содержит игру, тесты и универсальные сценарии развёртывания; личные данные администраторов и реальные конфигурации серверов в него не входят.

```sh
npm ci
npm run build
npm test
node scripts/privacy-audit.mjs
```

CI дополнительно проверяет установщики и игровой сайт. Для сборки требуется Node.js, совместимый с текущими зависимостями проекта.
