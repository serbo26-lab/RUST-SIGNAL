# РЖАВЫЙ СИГНАЛ / RUST SIGNAL

Браузерная игра с шестью эпизодами, персонажами, боссами, руководством и энциклопедией. Главная страница — `/`, игра — `/play/`. Для игроков установка программ не нужна.

Проект устанавливается **на VPS как веб-сайт**. Ниже — четыре **альтернативных**, а не последовательных способа установки. **Выберите один** в зависимости от того, как именно ваш сервер обрабатывает HTTP и HTTPS.

Все домены и пути в примерах условные. `game.example.com`, `/var/www/example-game`, `8443`, пути сертификата и имя SNI-переменной **не относятся к реальному серверу**. Подставьте свои значения только там, где это прямо указано.

## 1. Какой способ выбрать

| Что уже настроено на VPS | Выбирайте | Что получится |
| --- | --- | --- |
| Новый сайт: нужный домен **ещё не обслуживается другим Nginx-сайтом**; обычный системный Nginx или чистый VPS | **Способ 1 — обычная установка** | Сайт по HTTP + онлайн-рейтинг; HTTPS настраивается отдельно |
| Для домена **уже есть отдельный Nginx-сайт** (один или несколько выделенных HTTP/HTTPS-конфигов), который нужно полностью заменить игрой | **Способ 2 — замена существующего сайта** | Игра + онлайн-рейтинг на сохранённых Nginx-портах, с резервной копией; учитывайте предупреждение об ACME ниже |
| HTTPS/TCP-маршрутизация принадлежит VPN/proxy-программе или нестандартному серверу; есть **уже настроенный веб-каталог**, а конфигурации сети трогать нельзя | **Способ 3 — только файлы сайта** | Игра в существующем веб-каталоге, **без онлайн-рейтинга**, пока API не подключён отдельно |
| Публичный TCP/443 обрабатывает **именно Nginx stream**, его существующий SNI-`default` уже ведёт к внутреннему HTTPS-серверу Nginx, нужен ещё один отдельный домен | **Способ 4 — Nginx stream/SNI** | Отдельный HTTPS-сайт + онлайн-рейтинг без изменения существующих stream-маршрутов |

**Не определили схему сервера? Не запускайте установщик наугад.** Наличие VPN само по себе не означает, что нужен способ 4: он подходит **только** для конкретной конфигурации Nginx stream. Если домен уже занят, способ 1 не предназначен для его перехвата. Один и тот же домен нельзя независимо устанавливать сразу несколькими способами.

## 2. Что проверить до установки

Подключитесь к VPS по SSH и выполните на **самом VPS**, а не на домашнем компьютере:

```sh
sudo nginx -t
sudo ss -lntup
```

Проверьте, какое приложение использует TCP/80, TCP/443 и внутренние HTTPS-порты, есть ли у нужного домена `server_name` в Nginx, кто отвечает за сертификат и как он продлевается. Если Nginx отсутствует на чистом сервере, первая команда может не выполниться — способ 1 установит его при необходимости. Не публикуйте полный вывод `nginx -T` и приватные файлы сертификатов: в них могут быть сведения о вашей инфраструктуре.

**Важно:** при замене действующего сайта сначала сделайте независимый бэкап. Скрипты рассчитаны на отказ при неоднозначной конфигурации, но не могут гарантировать сохранение всех нестандартных правил другого ПО.

## Способ 1. Обычный Nginx — новый домен или HTTP по IP

**Используйте, если:** VPS новый или системный Nginx уже работает, но выбранный домен ещё не принадлежит другому виртуальному хосту. Скрипт собирает сайт, устанавливает Node.js/SQLite API и создаёт отдельный управляемый Nginx-конфиг. Доступ по домену сначала будет **HTTP**, не HTTPS.

### Установка с доменом

```sh
DOMAIN='game.example.com'
curl -fsSL https://raw.githubusercontent.com/serbo26-lab/RUST-SIGNAL/main/deploy/vps.sh -o /tmp/rust-signal-vps.sh
sh -n /tmp/rust-signal-vps.sh
sudo sh /tmp/rust-signal-vps.sh install "$DOMAIN"
```

**Изменить:** только `game.example.com` в первой строке — на **свой домен**, уже указывающий на VPS. Адрес GitHub и путь скачиваемого скрипта менять не требуется.

Если нужен сайт **только по IP и HTTP**, после скачивания скрипта вместо команды с `"$DOMAIN"` выполните `sudo sh /tmp/rust-signal-vps.sh install` (без аргумента). Никаких изменений портов 443 или HTTPS этот режим автоматически не делает.

### Обновление

```sh
curl -fsSL https://raw.githubusercontent.com/serbo26-lab/RUST-SIGNAL/main/deploy/vps.sh -o /tmp/rust-signal-vps.sh
sh -n /tmp/rust-signal-vps.sh
sudo sh /tmp/rust-signal-vps.sh update
```

При обновлении **не передавайте домен**: он уже записан в данных установки. Если на VPS создан особый HTTPS-прокси, проверьте его отдельно.

## Способ 2. Заменить уже существующий сайт в Nginx

**Используйте, если:** домен **уже обслуживается** выделенным Nginx-виртуальным хостом, и этот сайт разрешено заменить игрой целиком. Установщик проверяет конфигурации, сохраняет резервную копию, отключает только выбранные конфиги и старается сохранить их `listen` и TLS-сертификаты. Другие сайты и общий `default_server` заменять нельзя.

**Внимание — продление сертификата:** данный режим сохраняет основные TLS-параметры, но **не переносит все произвольные `location`**, включая специальные маршруты `/.well-known/acme-challenge/`. Если ваш сертификат продлевается через HTTP-01 в старом виртуальном хосте, **не применяйте этот режим без плана восстановления ACME-маршрута и проверки продления**. Для нестандартного proxy/VPN-конфига этот установщик также не подходит.

### Установка (замена)

```sh
DOMAIN='game.example.com'
curl -fsSL https://raw.githubusercontent.com/serbo26-lab/RUST-SIGNAL/main/deploy/replace-domain.sh -o /tmp/rust-signal-replace.sh
sh -n /tmp/rust-signal-replace.sh
sudo sh /tmp/rust-signal-replace.sh "$DOMAIN"
```

**Изменить:** `game.example.com` — на домен **уже существующего сайта, который вы намерены заменить**. Не вписывайте в команду IP, внутренний порт или путь сертификата: сценарий извлекает допустимые параметры из старого Nginx-хоста. При успешной установке он покажет расположение созданной резервной копии.

### Обновление

После установки способом 2 **не повторяйте `replace-domain.sh`**. Используйте обычное обновление из способа 1:

```sh
curl -fsSL https://raw.githubusercontent.com/serbo26-lab/RUST-SIGNAL/main/deploy/vps.sh -o /tmp/rust-signal-vps.sh
sh -n /tmp/rust-signal-vps.sh
sudo sh /tmp/rust-signal-vps.sh update
```

Оно использует сохранённый домен и оставляет созданный управляемый Nginx-конфиг.

## Способ 3. Только файлы в существующем веб-каталоге

**Используйте, если:** работающие Nginx/TLS/VPN/proxy-маршруты **вообще нельзя менять**, но известен каталог, из которого уже обслуживается нужный сайт.

**Условия:** каталог должен уже существовать, быть обычным каталогом (не ссылкой) и содержать `index.html`. Других посторонних файлов в его корне быть не должно, кроме допустимого `.well-known`. Установка заменит прежнюю страницу игрой. Скрипт не добавляет Nginx-сайт, не занимает порты и не подключает `/api/`: **онлайн-рейтинг без отдельной интеграции API не заработает**.

### Установка

```sh
DOMAIN='game.example.com'
WEBROOT='/var/www/example-game'
curl -fsSL https://raw.githubusercontent.com/serbo26-lab/RUST-SIGNAL/main/deploy/selfmask-webroot.sh -o /tmp/rust-signal-webroot.sh
sh -n /tmp/rust-signal-webroot.sh
sudo sh /tmp/rust-signal-webroot.sh install "$DOMAIN" "$WEBROOT"
```

**Изменить два значения:** `game.example.com` — домен сайта; `/var/www/example-game` — **полный существующий путь** к его веб-каталогу, уже указанному в работающей конфигурации вашего веб-сервера. Не подставляйте путь к каталогам чужих сайтов, сертификатам или VPN.

### Обновление

```sh
DOMAIN='game.example.com'
WEBROOT='/var/www/example-game'
curl -fsSL https://raw.githubusercontent.com/serbo26-lab/RUST-SIGNAL/main/deploy/selfmask-webroot.sh -o /tmp/rust-signal-webroot.sh
sh -n /tmp/rust-signal-webroot.sh
sudo sh /tmp/rust-signal-webroot.sh update "$DOMAIN" "$WEBROOT"
```

**Изменить:** оба значения на **те же**, что использовались при установке.

## Способ 4. Готовый шлюз Nginx stream/SNI

**Используйте только если одновременно выполняются все условия:**

1. Публичный **TCP/443** обрабатывает Nginx с модулем `stream` и `ssl_preread`.
2. В действующем `map $ssl_preread_server_name $tls_routes` существует `default`, который уже направляет на **внутренний HTTPS-сервер Nginx**, а не в VPN.
3. Вы знаете внутренний HTTPS-порт, имя SNI-переменной и пути **действующего** сертификата и закрытого ключа для нового домена. Новый домен ещё не обслуживается другим Nginx-хостом.

Это **не общий способ установки на VPN-сервер**. Если TCP/443 принадлежит другому приложению или маршруты выглядят иначе, скрипт должен отказаться от установки; применяйте способ 3 либо делайте отдельную ручную интеграцию.

### Установка

```sh
DOMAIN='game.example.com'
HTTPS_PORT='8443'
CERT='/etc/ssl/example-game/fullchain.pem'
KEY='/etc/ssl/example-game/privkey.pem'
MAP_NAME='tls_routes'

curl -fsSL https://raw.githubusercontent.com/serbo26-lab/RUST-SIGNAL/main/deploy/stream-default-site.sh -o /tmp/rust-signal-stream.sh
sh -n /tmp/rust-signal-stream.sh
sudo sh /tmp/rust-signal-stream.sh install "$DOMAIN" "$HTTPS_PORT" "$CERT" "$KEY" "$MAP_NAME"
```

**Заменить все пять значений:**

| Переменная | Что вписать |
| --- | --- |
| `DOMAIN` | Новый домен игры, например `game.example.com` |
| `HTTPS_PORT` | **Существующий** внутренний HTTPS-порт Nginx, на который уже указывает SNI-`default`; `8443` — лишь пример |
| `CERT` | Абсолютный путь к уже выданному сертификату **этого домена** (fullchain PEM) |
| `KEY` | Абсолютный путь к соответствующему закрытому ключу (PEM). **Не вставляйте содержимое ключа в команду или репозиторий** |
| `MAP_NAME` | Имя переменной, указанной в уже действующем `map` и `proxy_pass`, например `tls_routes`, **без знака `$`** |

Скрипт проверяет существующую SNI-схему и сертификат, собирает сайт, устанавливает приватный Node.js/SQLite API и добавляет отдельный HTTPS-хост. Существующие stream-маршруты не переписывает. **Сертификат он не выпускает.**

### Обновление

Повторите те же пять значений и замените `install` на `update`:

```sh
sudo sh /tmp/rust-signal-stream.sh update "$DOMAIN" "$HTTPS_PORT" "$CERT" "$KEY" "$MAP_NAME"
```

Перед обновлением скачайте свежий `stream-default-site.sh` по URL из блока установки. При неудачной первой публикации, если файлы игры и API уже подготовлены, вместо `update` предусмотрена команда `resume` с теми же пятью аргументами — **только для частично завершённой первоначальной установки**.

## Проверка после установки

Подставьте свой домен и проверяйте протокол, который действительно настроен:

```sh
DOMAIN='game.example.com'
curl -I "http://$DOMAIN/"
curl -I "http://$DOMAIN/play/"
```

Если на сервере **уже настроен публичный HTTPS**, проверяйте также:

```sh
curl -I "https://$DOMAIN/"
curl -I "https://$DOMAIN/play/"
```

Для способов 1, 2 и 4, где установлен API, проверьте по **реально работающему протоколу**:

```sh
curl "https://$DOMAIN/api/health"
curl "https://$DOMAIN/api/leaderboard?difficulty=veteran"
```

Не используйте `-k` для обхода ошибок TLS. Если HTTPS ещё не настроен (типичный случай способа 1), замените `https://` на `http://` в API-проверках. Код 200 на странице `/play/` подтверждает раздачу файлов, но не заменяет проверку игры в браузере.

## Онлайн-рейтинг и безопасность

В способах 1, 2 и 4 Node.js API доступен только локально на `127.0.0.1:32741` через обратный прокси `/api/`. SQLite располагается вне публичного сайта: `/var/lib/rust-signal/leaderboard/` с ограниченными правами. Каждый VPS имеет **свою** базу: установка на несколько серверов не создаёт общий рейтинг автоматически. Полностью предотвратить накрутку результатов браузерной игры без проверки игрового процесса сервером нельзя.

При любом способе не подменяйте системные правила VPN/TLS, не изменяйте чужие конфиги без разрешения и храните отдельный бэкап. Реальные IP, домены, схемы проксирования, конфигурации серверов, сертификаты и ключи **не следует добавлять в публичный GitHub**.

Для проверки и сборки из исходников необходима совместимая версия Node.js:

```sh
npm ci
npm run build
npm test
node scripts/privacy-audit.mjs
```
